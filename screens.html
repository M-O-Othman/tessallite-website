The same governed model, used by modellers, analysts, and Excel users.

Modeller workspace

Model Builder turns source tables into a governed business model.

The modeller screen is where a project owner defines the model before dashboards, SQL clients, Excel, and the agent can use it.

Modeller screen

The canvas shows the fact table in context with related dimensions, joins, model status, deployment state, and validation feedback. The modeller can move between the canvas, query panel, model health, and usage analytics without leaving the model.

  • Tables and joins show how the business model maps to source data.
  • Summary chips expose counts for tables, joins, dimensions, measures, aggregates, and target state.
  • Deployment and validation indicators show whether the model is ready for governed use.

Conversational analytics

Conversational agent screen

The agent screen lets a user ask in business language and receive a governed answer, not a raw table dump. The example shows a completed answer with an aggregate route badge, explanatory text, a chart, and expandable data.

  • Conversation history stays on the left, so users can return to previous questions.
  • Answers can include narrative, charts, tables, route badges, diagnostics, and supporting data.
  • The agent works from approved model terms, glossary context, persona scope, and the same query path used by other tools.

Excel and plugin workflow

Spreadsheet users keep Excel while Tessallite keeps the definitions governed.

Tessallite supports Excel through XMLA PivotTables and the Tessallite Excel add-in. Both paths use the deployed model, row security, personas, and approved measures. The add-in is served by your own Tessallite instance — the guide shows how to connect.

Connect Excel — step-by-step guide

Excel screen

The Excel connection workflow uses the XMLA endpoint so a workbook can browse Tessallite models as governed cubes. The add-in path adds a task pane for guided report building, agent questions, CUBE formulas, drill-through, trace, diagnostics, and glossary lookup.

  • Native PivotTables connect through the XMLA endpoint for slicers, timelines, subtotals, and drill-through.
  • The add-in works from the same deployed model and supports guided report building inside Excel.
  • Workbook numbers reconcile with dashboards and agent answers because they share the semantic layer.
